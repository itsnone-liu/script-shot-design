# 821 语音线调研：H3 原生对白乱码根因 + 系统语音能力升级方案

> 2026-09-18 · 起因：couple30 昨天交付的 take 被用户报两个问题——
> ① 女人正面脸不一致；② 更严重：说的话听不懂（语音线 821 从未做过）。
> 本报告 = 问题诊断 + MiniMax 官方/社区解法全景 + 我们的系统升级方案。
> 原始材料存 `output/research_voice/`（T8 features/readme、官方 H3 脚本、乱码修复文章、RH 搜索结果、候选工作流输入面）。

## 0. 两个问题的病根诊断

### 问题② 说话听不懂 —— 溯源已闭合
- ffprobe 证实：`output/creative_v2/couple30_v1/shots/` 10/10 take **全部自带 AAC 音轨**。
- 我们从未跑过 TTS（821 无任何音频产物）→ 用户听到的是 **MiniMax H3 原生联合音画生成的"对白"**。
- 这正是社区充分记录的 **H3 gibberish 失败模式**（seedance.tv 2026-08 专文）：音节含混、填充音重复、
  台词错配说话人、句子结束后继续发声。画面正常、语音完全不可用是典型表现。
- 根因（社区实践归纳，非官方披露）：H3 图像+声音**联合建模、一次前向**，不是独立可控的 TTS 管线。
  多语种提示冲突 / 长句音素边界压力 / 场景提示拥挤（双人+动作+配乐+运镜同段竞争）都会触发。
- **结论：H3 原生语音不可作为对白交付物。对白必须走独立语音管线。**

### 问题① 女人正面脸不一致
- couple30 链条：canonical_v6 转正组（已验收）→ ReActor 修正关键帧 → i2v take → 拼接。
- 缺的环节：**视频级逐帧身份修复从未做过**（concert30 有整套成熟管线：YuNet+SFace 逐帧、
  角色感知索引、切窗分段、h/w 闸门——没迁移到 couple30）。
- i2v 首尾帧锚定保首尾，13–14s 中段脸会漂；take 间方差叠加 → 正面脸观感不一致。
- 修法明确（不是研究题，是迁移题）：见 §4。

## 1. MiniMax 自己是怎么解决"说话视频"的（四层答案）

### 1.1 提示词工程层（官方规则，已在 820 KB 的官方模板 graph 2085314391548997633 中拿到全文）
官方 3 字段结构：
```
integrated_multimodal_description: <构图/主体/动作> 她（S1）说：<d>[Chinese] 确切台词</d> ...
overall_soundscape: 环境音衬托清晰人声
non_diegetic_music: N/A（有则写）
```
- **Digital Human Mode 触发条件**：数字人/口播/对口型/含台词文案 + 人物参考 → 强制口型同步描写。
- 铁律：`<d>` 标签内**只放确切台词**（带语言标签）；说话人 ID `(S1)/(S2)` 全程稳定；
  **一段一句台词**；台词秒数与片段时长严格匹配（5s 台词塞 15s 片段 → 必产生填充音/循环伪影）；
  音频与文案冲突时**文案为准、音频只作音色/节奏/情绪参考**；听不清的片段标 `[unclear]` 不许瞎猜。
- 官方推荐失败止损线：**严谨重试 3 次仍乱码 → 停止重掷**，改①再缩台词②转画外音空镜③保画面后期换对白。

### 1.2 参考音频层（官方数字人管线核心）
- H3/Ref2VA 输入面有 `ref_audios.ref_audio_0..2` + `ref_video_audios`：**参考音频 = 音色/语气/节奏锚**。
- 官方 API 有专用端点 **`/v2/h3_context_ir`**（官方仓库 scripts/readme/full-2k-ref2va-h3-context-ir.sh，
  已存 research_voice/）：发 "Character speaks: …Voice timbre follows reference audio 1" +
  reference_video(脸/动作) + reference_audio(音色) → 返回扩写好的完整 6 段提示词，供 H3-Base 生成。
- 即官方路线 = **干净语音先行（ref_audio 驱动）+ 台词进 `<d>` + 模型克隆音色并对口型**，
  而不是指望模型自由发挥原生对白。
- RH 上的现成实现（KB 卡 2090650431957954561）：`MiniMaxH3ReferenceToVideo` + LoadImage + LoadAudio，
  `match` 模式把参考音频时长与视频时长对齐 → 一图一音出口播片。

### 1.3 社区工程层（T8 生态，我们 RH 工作流正是 T8 节点族）
- **vocal_lock_audio 契约**：timeline 对齐的人声轨作为 lock_source 驱动 Ref2VA 每一场景
  （`local_mv_vocal_lock_v3_official_ref2v_advanced`，32s 五场景 MV 全链验收通过）。
- 关键工程结论：**H3 音频条件能驱动表演（口型/节奏跟随），但不是音素级口型求解器**
  （"mux_audio 保原声" ≠ "deterministic lip sync"）——所以仍要 SyncNet 量化验收。
- **双时钟采样器音频 sigma 修复**（v1.36.2）：pass-2 视频 sigma 0.9035 / H3 shift 12/3 时
  音频 sigma 必须 ≈0.701，否则自定义采样器损坏音频（与原生输出 PCM 相关性掉到 0.9491 才修复）。
  自建采样工作流做音频时必查此参数。
- QA 方法论（可直接抄）：**ASR 回读台词验证**（VAD+ASR 检出"你在哪里"级别）+
  **SyncNet 口型偏移闸门**（孤立人声轨 0/-1 帧@25fps 过；400ms 延迟视频控制组 +9 帧验证闸门灵敏度）+
  逐帧人脸跟踪 + 人耳全速盲审。

### 1.4 TTS 产品层（"真人语音模拟"的模型大概率指这里）
- **MiniMax speech-02-hd**（Replicate 95.6k runs）：300+ 预置音色、**10 秒语音克隆（官方称 99% 相似）**、
  30+ 语言、情感控制（auto/手动）、音高/语速/音量/停顿（`<#x#>` 精确到 0.01s）、5000 字上限。
  已迭代到 speech-2.6-hd。→ 与 H3 同厂，音色参考配套最顺（TTS 出音频 → ref_audio 进 H3）。
- 但用户已定"弃 MiniMax 官方 API 走 RH"→ RH 替代：**IndexTTS2**（webapp 2093959907870511105：
  情绪+文案+迁移音色三输入，1999133286062583810 带语气情感版）、FishAudio(2066944766679543809)、
  Qwen3-TTS(2019397955479937025)、FireRed Audio 编辑全家桶(2094466873518116865)、CosyVoice2。

## 3. 821 系统语音线升级方案（管线 v2）

### 3.1 新管线（在现有"脚本→关键帧→i2v→剪辑"后接音频线）
```
台词表(逐句: 角色/台词/情绪/时长预算)
  → TTS 生成逐句干声（IndexTTS2@RH 克隆音色 | MiniMax speech-02-hd | edge-tts 起步）
  → 唇同步（路线 B 后期重绘 或 路线 C 音频驱动再生成，按镜头选）
  → 混音（干声 + BGM + 环境声，响度对齐）
  → QA 闸门 → 交付
```

### 3.2 顺序定律（本调研最重要的一条工程结论）
> **ReActor 逐帧身份修复必须在唇同步之前**；唇同步之后禁止任何换脸操作。
> 理由：inswapper 保 target 表情但整脸重写——唇同步成果会被静态源脸覆盖。
> （concert30 先例：ReActor 修唱歌嘴型可行=保表情特性；但顺序反过来必毁。）

完整顺序：`take 选择 → ReActor 身份修复(双人角色感知) → TTS 唇同步(仅说话窗) → 混音 → QA`。
路线 C 注意：音频驱动再生成后**仍需身份闸门**（Ref2VA/i2v 裸身份弱是已证定律），修复仍在其后、
口型抽验在其后（inswapper 保表情 → 抽 3 帧验嘴型开合与音频包络对齐）。

### 3.3 新增 QA 闸门（把"听不懂"变成可量化指标）
| 闸门 | 工具 | 阈值（首版） |
|---|---|---|
| 可懂度门 | faster-whisper 本地 ASR 回读混音对白 → 与台词表算 CER | CER ≤ 15% 过（本地 torch 已备，装包即用）|
| 口型门 | SyncNet 偏移（T8 校准法）| ≤1 帧 过；并用 +400ms 延迟控制组验证闸门灵敏度 |
| 身份门 | 现行 SFace 角色感知逐帧（concert30 同款）| 现行阈值不变 |
| 人耳终审 | 全速播放盲听 | 用户/验收人 |

### 3.4 提示词侧预防（今后所有含台词镜头的生成合同加约束）
- 生成合同里台词进 `<d>[Chinese] …</d>`、说话人 `(S1)/(S2)` 锁定、一段一句、台词时长≈镜头时长；
- **原生音轨一律视为占位**：交付前替换为 TTS 干声+混音（`-an` 剥轨或整轨替换）；
- 声音偏好写 `overall_soundscape`（环境音可用原生），对白永不依赖原生。

## 4. 对昨天这条片的具体修复方案（待用户选）

**前置（两案共通）**：确认选版 A_T1/B_T2/C_T2 → 34s 底版合成 → 路线 A/B/C 分镜处理。

- **方案甲（保画面，推荐首选）**：`底版 → 逐帧 ReActor 修复（治问题①，concert30 管线迁移，
  A 段她=上脸索引实跑校准）→ 11 句 TTS 干声 → LatentSync 后期口型（A/C 段她的说话窗，
  2086650291638005762 按秒窗口或多人版 2086650599655108610）→ BGM 混音 → 三闸门 QA → 交付`。
  成本最低、画面零重掷；风险=趴姿 3/4 脸对口型效果需 1-2 次试投。
- **方案乙（原生口型，画面重掷）**：`11 句 TTS 干声 → 2095531397845889025 首尾帧+驱动音频再生成 A/C 段
  （关键帧当首尾帧）→ 身份闸门+ReActor 修复 → 混音 QA`。
  口型原生质量上限更高；成本=重掷全部对白镜头（~2 容器×best-of-N）+身份再修。
- 混合：A 段（她主说话+双人近景）走乙，C 段（结尾一句）走甲。
