# 821 故事创作、剧本和分镜升级方案

## 一、总体判断

821 当前的方向是正确的：先建立故事和编剧知识，再进入分镜与视频生成。参考 `drama-skills`、`video-shotcraft` 和 `FireRed-OpenStoryline` 后，主要需要补齐的不是新的生成模型，而是制作过程中的中间产物、审批闸门和可复用镜头知识。

目标链路调整为：

```text
创作简报
→ 故事概念室
→ 故事声明
→ 节拍表
→ 场景卡
→ 可拍剧本
→ 视觉圣经/资产表
→ 分镜表
→ 镜头配方
→ 提示词包
→ 用户确认
→ RH/MiniMax 生产
→ 可编辑时间线
→ 成片审查与经验回写
```

任何阶段失败，都回到对应阶段修改，不允许用后面的漂亮画面掩盖前面的故事问题。

## 二、故事创作层改造

### 1. 概念不再直接进入分镜

当前 `concept_candidates.json` 已经有目标、阻碍、产品角色和结果，但还需要增加一个明确的 `story_statement.json`，由用户选定一个概念后生成：

- 一句话 logline；
- 主题和观众承诺；
- 外部目标、内部需求和缺陷；
- 主要阻碍及升级方式；
- 产品在因果链中的角色；
- 片头状态和片尾状态；
- 不允许出现的捷径和支线。

这一步对应 `drama-skills` 的故事开发阶段。它的价值是把“一个好点子”变成“可以被检查的故事契约”。

### 2. 增加概念室的反方审稿

每个概念至少经过三个角色：

- `StoryEditor`：目标、冲突、因果和结尾；
- `AudienceAdvocate`：观众是否马上理解、是否愿意继续看；
- `BrandStrategist`：产品是否真正改变了人物或结果。

审稿不能只给总分，必须输出：具体问题、涉及字段、删除/改写建议。只有通过概念闸门，才生成节拍表。

### 3. 节拍表从“事件列表”升级为状态转换

每个 beat 固定为：

```text
state_in
→ visible_event
→ character_choice
→ state_out
→ causal_hook
```

30 秒广告至少包含：目标建立、阻碍出现、压力升级、产品相关转折、主动行动、可见结果、品牌收束。只有产品展示而没有状态改变的 beat 标记为冗余。

## 三、剧本生成层改造

### 1. 先生成场景卡，再生成可拍剧本

场景卡比直接写 Markdown 剧本更适合作为中间层。每张卡回答：

- 这一场让观众知道或感受什么；
- 人物此刻要什么；
- 谁/什么阻碍他；
- 他做了什么选择；
- 结束时什么发生变化；
- 哪些信息必须由画面表达。

剧本生成器只负责把场景卡翻译成动作、画面、必要对白和声音，不负责重新发明故事因果。

### 2. 剧本诊断器

新增 `script_diagnostics.json`，自动检查：

- 是否存在单一主线；
- 前 20% 时长是否出现目标；
- 中段是否出现可见阻碍；
- 转折是否改变人物行动；
- 结果是否由人物行动造成；
- 产品动作是否超过两次；
- 是否存在突然成功、无功能对白、无关人物和无关换装；
- 每个场景删掉后是否仍然没有影响。

诊断结果分为 `blocker`、`warning` 和 `note`。存在 blocker 时不能进入分镜。

## 四、分镜设计层改造

### 1. 从“镜头字段”升级为“镜头功能 + 镜头配方”

现有 `Shot` 字段已经包含景别、运镜、构图和连续性，但还缺少可复用的镜头配方层。参考 `video-shotcraft`，每个镜头应绑定一个 `shot_recipe_id`：

```json
{
  "recipe_id": "reveal_slow_dolly_in_v1",
  "story_functions": ["reveal", "emphasize"],
  "camera_move": "slow_dolly_in",
  "start_framing": "subject plus environment",
  "end_framing": "subject fills safe central area",
  "motion_curve": "ease_in_out",
  "recommended_duration": [3, 5],
  "best_for": ["product_reveal", "emotional_turn"],
  "failure_modes": ["subject drift", "over-fast movement"],
  "acceptance_tests": ["subject remains readable", "movement has narrative purpose"]
}
```

镜头设计流程变为：

```text
故事 beat 的功能
→ 选择景别和视线
→ 选择镜头配方
→ 填入人物/产品动作
→ 检查起止状态和下一镜衔接
```

不能先选一个漂亮运镜，再反过来寻找故事用途。

### 2. 增加 Coverage 选择

对于同一场景，可以生成 2–3 个镜头覆盖候选：

- 叙事清晰版；
- 产品强调版；
- 情绪/节奏版。

先选择能表达故事的 coverage，再决定是否保留视觉炫技镜头。这样可以吸收 `drama-skills` 的分镜确认思路，也避免一次性锁死错误镜头。

### 3. 把连续性写进分镜契约

每个镜头必须明确：

- 人物位置、服装和视线方向；
- 道具进入/离开状态；
- 动作开始状态和结束状态；
- 与前后镜头的方向和光线关系；
- 生成失败时可接受的替代动作。

## 五、生产与剪辑层改造

### 1. 分阶段审批

参考 `drama-skills` 和 `FireRed-OpenStoryline`，设置四个审批点：

```text
故事审批 → 剧本审批 → 分镜/提示词审批 → 生产审批
```

未审批的文件只能生成草稿，不能提交 RH。个人实验可以默认由用户一句“确认”通过，但系统仍需保存确认记录。

### 2. 可编辑时间线契约

最终交付不只保存 MP4，还要保存：

- 镜头素材路径；
- 入点、出点和速度；
- 转场；
- 字幕、Logo 和文字叠加；
- BGM、环境声、音效；
- 生成工作流和参考资产。

`edit_timeline.json` 应能重新生成粗剪，并允许替换单个镜头，不需要重做整片。

### 3. 复盘回写

每次生成后保存：

- 故事问题；
- 镜头失败类型；
- 哪个配方成功/失败；
- 人工评分；
- 重做原因和结果。

这些记录回写 `cases/` 和 `rules/`，形成真正属于 821 的生产经验，而不是只引用外部项目。

## 六、针对当前咖啡广告的实施顺序

不重新生成视频，按以下顺序推进：

1. 选择 `coffee_concept_01《最后一页》`；
2. 生成 `story_statement.json`；
3. 生成 6 个状态转换 beat；
4. 运行 StoryEditor、AudienceAdvocate、BrandStrategist 审稿；
5. 生成 4–6 张场景卡；
6. 通过剧本闸门后再生成分镜；
7. 从镜头配方库选择运镜和构图；
8. 用户确认分镜后才调用 RH。

这样可以把今天的 5 个故事概念，真正变成可拍、可审、可修改的产品级短片工程。
