# 821 编剧系统设计：从“会写文案”到“能构建故事”

目标不是让一个模型直接输出一篇看起来完整的脚本，而是让系统能够持续回答：

```text
观众为什么要继续看？
人物想要什么？
什么阻止了他？
事情为什么在这一刻发生变化？
产品/主题如何成为因果链的一部分？
结尾留下了什么记忆？
```

## 1. 编剧系统的基本原则

### 1.1 先故事，后镜头

脚本必须先通过故事闸门，才能生成分镜。禁止用漂亮镜头掩盖没有目标、冲突和结果的故事。

### 1.2 先筛选，后扩写

系统先生成多个不同方向的故事概念，再用评分和反方审稿淘汰大多数方案；不能把第一个想法直接扩写成完整脚本。

### 1.3 每个转折必须有因果

“人物喝了咖啡所以成功”不是完整因果。必须说明产品怎样改变了人物的选择、观察、行动或状态，并把变化拍出来。

### 1.4 短片只保留一条主线

30 秒广告优先采用一条目标链：

```text
目标 → 阻碍 → 选择/转折 → 行动 → 结果 → 品牌记忆
```

第二主角、换装、支线、无关职业展示和重复产品动作默认删除。

## 2. 中间产物

编剧系统必须产生可审查文件，而不是只返回一段 Markdown：

```text
creative_brief.json       创作任务、受众、平台、限制
concept_candidates.json   多个故事概念和评分
story_statement.json      logline、主题、人物欲望和冲突
character_bible.json      人物目标、恐惧、缺陷、选择
beat_sheet.json           按秒/节拍组织的故事变化
scene_cards.json          每场戏的目的、冲突、转折和退出条件
script.md                 可读脚本
script_diagnostics.json   结构、因果、注意力和品牌检查
revision_log.json         每轮重写理由和变化
```

## 3. 编剧流水线

### Phase A：创作简报

收集产品/主题、受众、平台、片长、禁用内容、品牌承诺和可用资产。若用户只有一句想法，先补齐缺失约束，不直接写脚本。

### Phase B：概念室

生成 3–5 个方向，至少覆盖不同的：

- 人物目标；
- 冲突类型（时间、误解、选择、能力限制、外部事件）；
- 产品在故事中的角色（工具、触发器、证明、陪伴、反差）；
- 结尾记忆点。

每个概念输出一句 logline：人物 + 目标 + 阻碍 + 独特转折 + 结果。概念评分维度为冲突清晰度、30 秒可拍性、产品因果、情绪变化、视觉可表现性和新鲜度。

### Phase C：故事圣经

锁定人物的外部目标、内部需求、当前缺陷、选择压力、关键道具、空间和视觉规则。广告片不需要完整人物传记，但必须知道人物在片头和片尾的状态差异。

### Phase D：节拍设计

先写 5–7 个 beat，不写对白：

```text
状态建立 → 目标出现 → 第一次失败 → 转折线索 → 主动行动 → 结果 → 品牌收束
```

每个 beat 必须包含：起始状态、事件、人物选择、状态变化、下一 beat 的因果钩子。若一个 beat 只有“展示产品”而没有状态变化，应退回重写。

### Phase E：场景卡

把 beat 转成场景卡，每张卡回答：

- 这场戏想让观众知道/感受什么？
- 人物此刻要什么？
- 谁或什么阻碍他？
- 他做了什么选择？
- 结束时什么发生了变化？
- 哪个信息必须用画面表现，不能用旁白解释？

### Phase F：脚本与对白

先写动作和画面，再决定是否需要对白。30 秒广告默认无对白；需要旁白时，旁白只承担画面无法表达的品牌观点，不描述观众正在看到的动作。模型生成的语音不直接进入交付。

### Phase G：编剧室审稿

至少进行三轮不同角色审稿：

1. `StoryEditor`：结构、因果、节奏和结尾；
2. `AudienceAdvocate`：观众是否马上理解、是否愿意继续看；
3. `BrandStrategist`：产品是否真正参与故事、品牌记忆是否清楚；
4. `ProductionEditor`：30 秒内是否可拍、是否超出生成能力；
5. `AdversarialReviewer`：主动寻找俗套、逻辑跳跃和注意力转移。

审稿人不能只给总分，必须指出具体 beat、具体台词或具体镜头的问题，并给出替代方案。

## 4. 质量闸门

### Story Gate

- 一句话能说清人物目标和阻碍；
- 至少有一次可见失败或压力升级；
- 转折改变人物行动，不只是改变背景音乐；
- 产品/主题是因果链的一部分；
- 结尾展示结果，不是重复动作；
- 饮用、拿取或展示产品的动作不超过故事需要。

### Script Gate

- 每个 beat 都有状态变化；
- 没有“突然成功”；
- 没有无功能对白；
- 画面、声音和后期文字职责分明；
- 片长、场景数量和演员数量可执行。

### Rewrite Gate

重写必须说明：保留什么、删除什么、改变哪个因果关系、为什么更好。系统不得仅以“更有电影感”作为修改理由。

## 5. 适合 821 的实现顺序

1. 先实现 `creative_brief`、`concept_candidates` 和 `beat_sheet` 的 JSON 模型；
2. 为咖啡广告建立 5 个可复用故事模板，并用反方审稿淘汰“连续喝咖啡”类方案；
3. 先让系统输出故事和节拍，由人确认后才生成分镜；
4. 再实现 `scene_cards` 到分镜表的转换；
5. 最后接入 RH 生产和成片质检。

在这条链路完成前，不继续通过增加提示词来掩盖故事层缺陷。
